# 序 · Dayline · GitHub Pages

可编辑的日程、成长任务与公开机会研究网页。沿用最新 v9 的四主导航、下一步卡片、任务验收与撤销、手机布局。GitHub Pages 版本由 GitHub Actions 构建发布，无需 ChatGPT 登录。

## 已提供的功能

- 今日 / 周历：编辑安排、按日期勾选、保留单次与重复日程。
- 计划：编辑目标与验收步骤，完成后推进到后续就绪任务，支持撤销。
- 发现：从固定公开来源生成机会与需求 JSON，展示原始时间、来源健康及证据限制。
- 助手：本机计划工具可用，独立私人后端已部署，可在本页使用访问密码登录并发送问题。2026-10-17 的唯一真实短测试遇到模型账户额度或速率限制，尚未取得真实回复；后台登录、健康检查和 CORS 已验证。GitHub Pages 不运行模型服务端，密钥不放入浏览器。状态与接入见 [内嵌聊天](standalone/PAGES-CHAT.md)。
- 手机：Safari 添加到主屏幕，保留安全区、16px 输入、主要触控区域与减少动画支持。尚无推送、个人云同步或离线聊天。

初始公开数据保留 104 个每周窗口、16 个种子目标与个人月预算；不包含姓名、GPA、排名或家庭资产。后续个人编辑、勾选、收藏与对话记录保存在当前浏览器。电脑、手机和不同网址之间不会自动同步。

## 发布

首次在仓库 Settings → Pages → Build and deployment → Source 选择 GitHub Actions。随后推送 main 分支，Pages 工作流会安装锁定依赖、采集公开资料、构建并发布。正式地址以成功部署的 GitHub Pages environment 为准；看到源码提交不等于网站已经上线。

本机使用 Node 24：

```text
pnpm install --frozen-lockfile
pnpm run build:pages
```

构建结果为 `pages-dist/`，只上传该目录。根脚本 /api 的 Node 与 Worker 服务不在 GitHub Pages 运行。日程和任务无需后台即可使用。

定时任务每四小时检查固定公开资料，可能延迟；不是实时交易信号或盈利保证。请求失败时保留旧快照并显示实际时间和失败来源，不伪造新鲜结果。公开仓库的定时工作流长期无活动可能停用，可在 Actions 手动恢复或运行。

## 数据迁移

先在旧站右上角设置导出备份，再在新站设置导入，核对目标和完成进度；对话另行导出。GitHub Pages 各项目共享账号域名，本版本使用应用与项目路径命名空间降低记录碰撞；它不构成对同源其他脚本的安全隔离。

## 安全配置

仓库、网页资产和 JSON 中不包含真实环境文件、模型密钥、私人登录哈希或运行缓存。前端不收集 API 密钥；接入页面内真实 AI 必须另行配置可信服务端、私人认证和调用限额。

Telegram webhook 与微信小程序没有随静态网站上线。它们仍需各自账号、服务端与平台适配。
